Anetos v0.5.0 is out. It's the first public release of the framework:
everything installs from the Go module proxy, and the
[docs](https://docs.anetos.dev/) are versioned from here on.

```sh
go install anetos.dev/anetos/cli/cmd/anetos@latest   # Go 1.26 or later
anetos new blog && cd blog
go tool anetos dev
```

<!--more-->

## What Anetos is

Anetos is a web framework for Go with the parts most web apps need in
one place: routing and handlers on `net/http`, a data layer with
migrations and generated model code, templ views, sessions and forms,
accounts and roles, queues, events, the scheduler, mail, file storage,
full-text search and search by meaning, AI providers, translations and an admin.
The web server, queue workers, listeners and scheduler run together in
one binary, or split by process type when you scale.

It's built the Go way: typed handlers, code generation instead of
runtime magic, and `net/http` all the way down. The router is an
`http.Handler`, middleware is `func(http.Handler) http.Handler`, and
any `http.Handler` can serve a route. The heavy dependencies (database drivers,
cloud SDKs, AI SDKs) live in modules of their own, so an app only pulls
in what it uses.

## What's new in v0.5

- **Installs with `go install`.** The `anetos` command, the framework
  and its driver modules are published together under one version.
- **Interface components in every web project** (`views/ui`), and a choice
  of CSS framework: Pico, Bootstrap, Bulma, Tailwind CSS or none.
  `go tool anetos css:use` switches an existing app.
- **One vocabulary** across settings, commands and the API, with a
  [glossary](https://docs.anetos.dev/concepts/glossary/).
- **Projects ready for coding agents.** `anetos new` writes `AGENTS.md`
  and skills for the common tasks; the docs ship inside the tool, at
  your version, offline (`go tool anetos docs`); `go tool anetos check`
  generates, builds, vets, tests and checks the app in one step; the app
  describes itself as JSON; and an MCP server gives agents the same.
  [Guide](https://docs.anetos.dev/getting-started/coding-agents/).
- **A security check** of the app's code, dependencies, routes, settings
  and running site, mapped to the OWASP Top 10, with SARIF reports for
  GitHub's code scanning (`go tool anetos security:check`).
  [Guide](https://docs.anetos.dev/guides/security-check/).
- **Contributor docs, governance and a code of conduct**, for anyone who
  wants to help.

The full list is in the
[changelog](https://github.com/anetos-dev/anetos/blob/v0.5.0/CHANGELOG.md),
and coming from v0.4, the
[upgrade guide](https://docs.anetos.dev/upgrade/v0.5/) has the steps.

## Where it stands

Anetos is early. APIs will still change before 1.0, and each change is
written up in the changelog and the upgrade guide of the release that
makes it. The [roadmap](https://github.com/anetos-dev/anetos/blob/main/docs/planning/roadmap.md)
says what's next.

## Try it, tell us

The [tutorial](https://docs.anetos.dev/getting-started/tutorial/) builds
an issue tracker step by step, and the
[API tutorial](https://docs.anetos.dev/getting-started/build-an-api/) a
JSON API. Questions and ideas go to
[GitHub Discussions](https://github.com/anetos-dev/anetos/discussions),
bugs to the [issues](https://github.com/anetos-dev/anetos/issues), and
vulnerabilities privately, as the
[security policy](https://github.com/anetos-dev/anetos/security/policy)
says.
